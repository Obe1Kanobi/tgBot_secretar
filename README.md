# 🤖 Meeting Bot — анализ встреч (демонстрационный проект)

[Node.js](https://nodejs.org)
[Docker](https://docker.com)
[Gemini](https://ai.google.dev)
[Telegram](https://core.telegram.org/bots)
[Bitrix24](https://www.bitrix24.com)

**Демонстрационный бот для анализа встреч**: автоматическая запись, транскрипция через Gemini AI, структурированный анализ по чек-листу и интеграция с CRM Битрикс24.

> **⚠️ Дисклеймер:** проект создан в целях демонстрации навыков разработки (портфолио) и **не предназначен для коммерческого использования** — развёртывание в реальном продакшене происходит на ваш страх и риск. Проект содержит существенные ограничения безопасности: браузер работает без sandbox и с отключённой веб-безопасностью (`--disable-web-security`), у API-эндпоинта нет аутентификации, команды Telegram-бота не фильтруются по чату. Подробнее — в [SECURITY.md](SECURITY.md).

## 🚀 Возможности

- **Автоматическое подключение к встречам** через Puppeteer (Google Meet, Zoom, Яндекс Телемост, Контур.Толк, MS Teams)

## ⚡ Быстрый старт

> **Важно:** бот рассчитан на Linux-окружение (PulseAudio, FFmpeg, Xvfb) — на Windows полноценно он не заработает. Рекомендуемый способ запуска — **Docker на Linux-сервере** (см. ниже).
>
> **Ещё один нюанс:** проект не использует `dotenv`, поэтому `npm start` сам по себе **не читает файл** `.env` — переменные окружения подхватываются только через Docker (`--env-file` / `env_file` в compose) или если экспортировать их вручную.

```bash
# Клонируем репозиторий
git clone https://github.com/ragnarook888-ai/bot-secretar
cd bot

# Устанавливаем зависимости
npm install

# Копируем шаблон переменных окружения
cp .env.example .env

# Редактируем .env — вписываем свои ключи
# (nano — консольный редактор Linux; на Windows просто откройте файл в редакторе)
nano .env

# Запуск (только Linux, переменные нужно экспортировать вручную)
npm start
```

Сервер запустится на `http://localhost:3000`

### Требования

- Node.js 18+
- npm или yarn
- Docker (рекомендуется — для контейнерного развёртывания)
- Chrome/Chromium (в Docker устанавливается автоматически)



### Локальная установка

```bash
# Установка зависимостей
npm install

# Пропустить скачивание Chromium, если Chrome уже установлен
PUPPETEER_SKIP_DOWNLOAD=true npm install
```



### Установка через Docker (рекомендуемый способ)

```bash
# Сборка образа
docker build -t meeting-bot .

# Запуск контейнера (одной строкой — многострочные команды с \ часто ломаются при вставке в SSH)
docker run -d --name meeting-bot --restart unless-stopped --env-file .env -e PORT=10000 -p 3000:10000 meeting-bot
```

> Флаг `-e PORT=10000` обязателен: проброс портов `3000:10000` ожидает, что приложение внутри контейнера слушает порт 10000, а в `.env` записан порт 3000.

Либо через Docker Compose (там переопределение порта уже прописано):

```bash
docker compose up -d --build
```

> Если видите ошибку `unknown shorthand flag: 'd' in -d` — на сервере нет плагина Compose v2. Установите `docker-compose-plugin` из официального репозитория Docker, попробуйте старую команду `docker-compose up -d --build` или запускайте без compose через `docker run` (см. выше).

## 💻 Использование

### Режимы работы

Бот работает в одном из двух режимов. Стартовый режим задаётся переменной `BITRIX_ENABLED` в `.env`, а переключается на лету командой `/bitrix` в Telegram — без перезапуска бота.

**Обычный режим** (по умолчанию, `BITRIX_ENABLED=false`)

Бот записывает встречу, транскрибирует её через Gemini и отправляет отчёт в Telegram. Анализ по чек-листу и обращения к Битрикс24 **не выполняются** — интеграция полностью выключена.

**Режим Битрикс24** (`BITRIX_ENABLED=true` или `/bitrix on`)

Помимо транскрипции и отчёта в Telegram дополнительно выполняются:

- структурированный анализ по чек-листу продаж из 12 пунктов;
- обновление лида в Битрикс24 при указании `leadId` (команда `/process [ссылка] [ID_лида]`) — анализ записывается в комментарий, стадия меняется по категории клиента, добавляются активность и задача.

### Команды Telegram

- `/start` — приветствие и инструкции
- `/process [url]` — обработать встречу (транскрипция и отчёт в Telegram)
- `/process [url] [leadId]` — обработать встречу и обновить лид в Битрикс24 (только в режиме Битрикс24)
- `/bitrix on|off|status` — включить/выключить режим Битрикс24 или показать текущий (без аргумента — тоже статус)
- `/test` — проверка связи с ботом

Пример:

```
/process https://meet.google.com/abc-defg-hij L12345
```

> Telegram-бот работает через long polling (сам опрашивает серверы Telegram), поэтому для команд Telegram открывать порты наружу не нужно.

### Как проходит обработка

1. **Получение запроса** → команда в Telegram или вызов API
2. **Запуск браузера** → Puppeteer открывает ссылку на встречу (на виртуальном экране Xvfb)
3. **Автовход** → логика подключения под конкретную платформу
4. **Старт записи** → FFmpeg захватывает системный звук через PulseAudio
5. **Длительность встречи** → ожидание таймаута или сигнала окончания
6. **Остановка записи** → сохранение аудиофайла
7. **Транскрипция** → Gemini AI превращает звук в текст
8. **Анализ** → оценка по чек-листу из 12 пунктов (только в режиме Битрикс24)
9. **Обновление CRM** → обновление лида в Битрикс24 (только в режиме Битрикс24, если указан leadId)
10. **Доставка отчёта** → сообщение администратору в Telegram

## 🐛 Решение проблем



### Частые проблемы

**1. Ошибки Puppeteer/Chrome**

```bash
# Установка зависимостей Chrome
apt-get install -y chromium-browser

# Или используйте Docker — там все зависимости уже есть

```

**2. Проблемы с записью звука**

```bash
# Проверить, работает ли PulseAudio
pulseaudio --check

# Проверить установку FFmpeg
ffmpeg -version
```

**3. Ошибки API-ключей**

- Проверьте, что `GEMINI_API_KEY` действителен
- Проверьте квоту API в Google Cloud Console
- Убедитесь, что в `.env` нет лишних пробелов в конце строк

**4. Telegram-бот не отвечает**

- Проверьте правильность `TELEGRAM_BOT_TOKEN`
- Убедитесь, что бот не заблокирован администратором
- Посмотрите логи polling на предмет ошибок

**5. Ошибка** `unknown shorthand flag: 'd' in -d`

- На сервере нет плагина Compose v2 — установите `docker-compose-plugin` или запускайте через `docker run` (см. раздел «Развёртывание»)

**6.** `docker run` **пишет** `requires at least 1 argument`

- При вставке многострочной команды потерялось имя образа в конце — вставьте команду одной строкой

**7. Проблемы с памятью**


## 🔍 Как работает бот — подробный разбор

### Два способа общения с ботом

У бота две «двери», через которые он принимает задания:

1. **Telegram (основной способ).** Бот работает через **long polling**: он сам каждые 300 мс опрашивает серверы Telegram «есть ли новые сообщения для меня?». Никаких входящих портов для этого не нужно — соединение всегда исходящее. Бот реагирует на команды `/start`, `/help`, `/test`, `/bitrix` (переключение режима Битрикс24) и главную — `/process`.
2. **HTTP API** — эндпоинт `POST /process-meeting`. Именно он выполняет всю работу. Команда `/process` в Telegram под капотом просто отправляет запрос на этот же эндпоинт внутри сервера (`http://localhost:PORT/process-meeting`).

### Полный цикл: от команды до отчёта

Вы пишете боту в Telegram:

```
/process https://telemost.yandex.ru/j/12345
```

Дальше происходит следующее:

1. **Telegram-обработчик** извлекает из сообщения ссылку и ID лида, отвечает «🚀 Начинаю обработку встречи...» и передаёт задание HTTP-эндпоинту вместе с ID чата, откуда пришла команда.
2. **Puppeteer запускает Chrome** на виртуальном экране Xvfb (в контейнере нет монитора, поэтому экран «рисуется» в память). По домену ссылки определяется платформа: `telemost.yandex` → Телемост, `meet.google` → Google Meet, `zoom` → Zoom и т.д.
3. **Бот пытается войти на встречу**: для каждой платформы прописан свой сценарий — ввести имя «Meeting Bot» в поле имени, нажать кнопку «Войти»/«Присоединиться» (перебирается список известных селекторов кнопок), выключить свой микрофон и камеру. Если ни один селектор не подошёл, используется запасной вариант — поиск любой кнопки со словами «join/войти/присоединиться» через JavaScript.
4. **FFmpeg начинает запись звука** через PulseAudio с устройства `default.monitor` — это «монитор» системного звука, то есть записывается всё, что *звучит* в контейнере (речь участников встречи из браузера), а не микрофон. Формат: WAV, моно, 16 кГц — этого достаточно для распознавания речи. Файл пишется в `/tmp/recordings/<uuid>.wav`.
5. **Бот ждёт** — см. важный нюанс ниже.
6. **Запись останавливается**, файл проверяется (существует, не пустой).
7. **Транскрипция**: WAV-файл целиком кодируется в base64 и отправляется в gemini-3.8-flash с промптом «транскрибируй, укажи говорящих». Ответ — текст разговора. **После транскрипции аудиофайл удаляется с сервера.**
8. **Анализ**: транскрипт отправляется в Gemini вторым запросом с чек-листом из 12 пунктов (боли клиента, возражения, ошибки менеджера, тон беседы и т.д.). Ответ приходит в JSON: общая оценка 0–100, оценка и комментарий по каждому пункту, резюме, категория клиента A/B/C.
9. **Битрикс24** (только в режиме Битрикс24, если передан ID лида и настроен вебхук): бот обновляет лид — записывает анализ в комментарий, меняет стадию по категории (A → «в работе», B → «обработан», C → «отказ») и добавляет активность «встреча».
10. **Отчёт уходит в Telegram** — в тот чат, откуда была команда `/process` (если задание пришло напрямую через API без указания чата — в `ADMIN_CHAT_ID`). В отчёте: оценка, категория, разбор по пунктам, резюме и первые 500 символов транскрипта.

> Шаги 8–9 выполняются только в режиме Битрикс24. В обычном режиме после транскрипции (шаг 7) бот сразу отправляет отчёт в Telegram.

### Хранится ли отчёт на сервере?

**Нет.** Аудиозапись удаляется сразу после транскрипции, транскрипт и анализ существуют только в памяти процесса и уходят в Telegram (и в Битрикс24, если настроен). Если сообщение в Telegram не дошло — данные потеряны. На сервере остаются только логи (без текста встречи).

### Когда бот перестаёт слушать встречу?

Это важный честный момент: **бот не умеет определять, что встреча закончилась.** Он записывает ровно `REC_MAX_SECONDS` секунд (по умолчанию 3600 = 1 час) и только потом останавливается — даже если встреча закончилась через 15 минут, он будет «сидеть» в пустой комнате до конца таймера, а отчёт вы получите только через час. И наоборот: если встреча идёт дольше — запись оборвётся на часе.

Практический совет: если встречи обычно короче, уменьшите `REC_MAX_SECONDS` в `.env` (например, `1800` для 30 минут).

### Как понять, что бот присоединился к встрече?

Два способа:

1. **В самой встрече** появится участник с именем **Meeting Bot** — это самый надёжный признак.
2. **В логах** (`docker logs -f meeting-bot`): строка `Successfully joined the meeting` и перед ней шаги вида `Clicked Telemost join button`. Если селекторы кнопок не сработали, там будут предупреждения `Name input not found`, `Could not mute microphone` и т.п.

Учтите: логика входа — это, по сути, «нажимание кнопок вслепую» по известным селекторам. Платформы регулярно меняют вёрстку, поэтому вход может ломаться; ошибка входа не всегда фатальна — бот может продолжить запись, даже если реально не вошёл (запишется тишина). Если отчёты стали приходить пустыми — первым делом проверяйте логи входа.

### Зачем нужен ADMIN_CHAT_ID?

Изначально это был **единственный** адрес доставки отчётов — все результаты слались только в этот чат, где бы вы ни вызвали команду. Сейчас отчёт приходит **в тот чат, откуда вызван `/process`**, а `ADMIN_CHAT_ID` стал запасным адресом: он используется, только когда задание приходит напрямую через HTTP API (например, из Битрикс24 или через `curl`), где «чата-источника» нет. Так что переменная больше не обязательная — если вы работаете только через Telegram, её можно оставить пустой.

### Известные ограничения

- **Длинные записи не пролезут в Gemini.** Аудио отправляется в запросе целиком (inline base64), а лимит Gemini на такие данные — около 20 МБ. WAV 16 кГц моно занимает ~2 МБ в минуту, значит надёжно транскрибируются записи примерно до **7–8 минут**. Часовая запись (~115 МБ) не пройдёт — для длинных встреч нужно переходить на Gemini Files API или резать файл на части.
- **Заглушка при ошибках API.** Если Gemini отвечает ошибкой ключа или квоты, бот вместо реальной транскрипции возвращает **демо-транскрипт** (выдуманный диалог менеджера с клиентом) — отчёт при этом выглядит настоящим. Если отчёт кажется «не про вашу встречу», проверьте `GEMINI_API_KEY` и квоту.
- **Одна встреча за раз.** Обработка синхронная: пока идёт одна встреча (до часа), вторая команда `/process` запустит параллельный Chrome и запись — они будут писать один и тот же системный звук и мешать друг другу.
